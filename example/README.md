# example/

A fictional user's brain, fully populated. **Sam Rivera**, a freelance developer trying to turn a
side project into something that pays rent.

Nothing here is real and nothing here is loaded by anything. It exists for one reason: a blank
template teaches you the file names but not the texture, and the texture is where people get it
wrong. Read `goals.md` and `queue.json` here before you write your own.

| File | Look at it for |
|---|---|
| `brain/goals.md` | How specific a top-3 has to be to actually break ties |
| `brain/brain-state.md` | What a real state file looks like at 60 lines, not 150 |
| `brain/facts-core.md` | How atomic "one fact per line" really means |
| `brain/queue.json` | Row shape, and the ratio of parked ideas to live tasks |
| `brain/rules.local.md` | The kind of correction that earns a line here |

## The three things worth copying

**The goals are falsifiable.** "Grow the business" would be useless. "Fifteen paying users by
March 1, so I can stop taking client work" makes every tie-break obvious, and that's the only job
this file has.

**Most ideas are parked.** Sam's queue has more parked ideas than live tasks. That's correct and it
is what the system is for. The parked ones are captured so they stop interrupting, not so they get
built.

**`rules.local.md` is short and specific.** Five lines, each one a correction that had already
happened twice. It isn't a personality description, and it shouldn't be.
